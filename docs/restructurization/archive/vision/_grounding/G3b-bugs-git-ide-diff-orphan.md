# G3b — Bug Audit: git / ide / diff_analysis / orphan

**Scope:** `src-tauri/src/git/`, `src-tauri/src/ide/`, `src-tauri/src/diff_analysis/`, `src-tauri/src/orphan/`
**Method:** read-only line-by-line audit; every claim carries `path:line`
**Date:** 2026-08-31
**Status:** COMPLETE

> **Headline:** git is a **git2-rs (libgit2)** wrapper — no shell-out, no PATH dependency, no injection surface.
> The IDE module contains **four arbitrary-file-read/write primitives reachable from the webview**.
> The orphan reconciler's TTL fallback **can never fire** (GI-01) and its cross-machine guard is **void on Linux/macOS** (GI-105).

## PART 2: MODULE NARRATIVES

### git/ (1,650 lines)

A synchronous wrapper around **git2-rs (libgit2)** — not a shell-out. Evidence: `git2::{Repository, RepositoryInitOptions}` at `git/repo.rs:8`, `git2::BranchType` at `branch.rs:3`, `git2::{Diff, DiffOptions}` at `diff.rs:8`. There is no `std::process::Command` anywhere under `git/`. **No PATH dependency, no shell quoting surface, no subprocess timeout question**, and branch/ref names reach libgit2 as C strings rather than argv — GI-48 is a refspec-construction issue, not injection.

(For completeness: the *other* half of the app does shell out to `git` — `graph/changes.rs:148` and `graph/incremental.rs:31` run `git diff` via argv with no timeout, and both convert a non-zero exit into an empty result set with only a `warn!` — a silent "no changes" answer.)

Three of twelve files are wholly or largely unreachable: `merge.rs` has zero callers (GI-08) and is internally broken four ways (GI-09 through GI-13). `history.rs:105 commit_diff` returns a stat sentence where its doc promises a unified patch, on the strength of a **false claim** that git2 lacks patch printing (GI-17) — the correct call is used forty lines away at `diff.rs:83`.

The parts that *are* wired up carry the destructive defects: `discard_changes` with an empty file list becomes a whole-worktree force-revert (GI-06), reachable from the UI in one unconfirmed click (GI-07); `stage` inherits libgit2's "empty pathspec means everything" (GI-32); `push` returns `Ok(())` on server-side rejection (GI-14) — the most misleading defect in the module; fast-forward pull force-checkouts over uncommitted work (GI-15); `force=true` deletes the current HEAD branch (GI-37).

`checkpoint.rs` — the undo system the agents depend on — reads files with no size cap (GI-24), restores without snapshotting first while its doc claims otherwise (GI-23), swallows every failure at `debug` level (GI-25), and opens a fresh unpooled SQLite connection with no busy timeout per operation (GI-27).

### ide/ (1,456 lines)

Containment is the headline failure, and it is **inconsistent per file**. `file_tree.rs:201`, `file_reader.rs:153`, and `file_search.rs:223` each implement their own check; `symbols.rs:23` and `symbol_nav.rs:222` implement **none at all**. Both are exposed as registered Tauri commands, so `get_symbol_tree` and `resolve_symbol` are **arbitrary-file-read primitives** (GI-02, GI-03).

The three checks that do exist share one weakness. Tracing `file_reader.rs:153-165`: line 157 canonicalizes the workspace with a raw-path fallback, 158 does the same for the target, 159 compares with `starts_with`. When **both** canonicalize calls fail — reachable because `load_workspace_dir()` returns a stored string with no existence check — the comparison runs on raw paths with `..` intact, `starts_with` matches component-wise on the leading components, and line 165 returns `abs` with the `..` still in it for the OS to resolve (GI-51, GI-52).

Separately, the tree walk follows symlinks out of the workspace: `file_tree.rs:157` classifies a directory symlink as "not a dir" via `DirEntry::file_type` (does not follow), so it escapes the placeholder branch and is then recursed into by `build_node`'s `fs::metadata` (`:86`, does follow) with no re-check (GI-54). The write side is worse — `ide_commands.rs:154` and `:177` never containment-check the *destination* of a rename or move (GI-04), and `delete_file` calls `remove_dir_all` while its doc says "empty directory" (GI-05).

Functionally, quick-open is broken by design: `file_search.rs:79` truncates at `4 × max_results` in walk order and only then sorts by score (GI-66); and if the workspace root's own basename is in `SKIP_DIRS`, `filter_entry` rejects the root and search returns nothing at all (GI-67).

### diff_analysis/ (548 lines)

Alive and reachable — the QC agent's `AnalyzeDiffTool` is the real consumer; the two Tauri commands have no frontend callers. Pipeline: parse → structural score → one LLM classification call.

The parser is **hand-rolled** and splits on `"\ndiff --git "`. Three inputs break it (GI-87, GI-88, GI-90). Nothing panics and nothing loops forever — the parser is linear and infallible; its failure mode is **silently wrong data**, which its `Result` return type (never `Err`) actively disguises (GI-92).

Downstream, unanchored substring matching scores `author.rs` as `auth` (GI-99), and `max_tokens: 512` guarantees truncation for a four-field JSON response — after which `mod.rs:44`'s `?` discards the free, deterministic structural score along with it (GI-94, GI-95), even though `ChangeClassification::Unknown` and its unused `Default` impl exist for exactly this fallback.

### orphan/ (239 lines)

An "orphan" is a task in `assigned`/`in_progress` whose claiming worker process is gone. **The output is genuinely read**, end to end: `reconcile()` → `events::emit_orphans_released_global` → `task:orphans-released` → `src/components/dashboard/OrphanAlert.tsx:23` → mounted at `src/tabs/AutoDevPanel.tsx:1191`. The structure is not dead; the *manual* half is (GI-114).

What is broken is the detection logic. **The TTL fallback — the path covering every task without a PID and every cross-host claim — cannot fire** (GI-01): `parse_from_rfc3339` is used on a column written by SQLite's `datetime('now')`, which is not RFC 3339. Any task assigned through the UI is stuck permanently, and with GI-114 there is no manual release either.

**The multi-machine guard is equally void on Unix** (GI-105): `current_hostname()` falls back to `"unknown"` with no syscall, so every Linux and macOS machine reports the same value and `same_host` is always true — a second machine will PID-check and release another machine's live work.

Finally, the module's own doc at `:16` ("does not block the executor (no async I/O)") is contradicted by `:89`'s `block_on` and by five synchronous SQLite calls, all on a tokio worker thread (GI-106, GI-107).

## PART 3: CROSS-PLATFORM PORTABILITY

- `orphan/mod.rs:198` — `COMPUTERNAME` is Windows-only; the `HOSTNAME` fallback is a non-exported bash variable. **Breaks on Linux and macOS** (always `"unknown"`), defeating the cross-machine PID guard (GI-105).
- `db/tasks.rs:892` — the same chain on the writer side. **Breaks on Linux and macOS**; guarantees reader and writer agree on the wrong answer.
- `git/history.rs:44` — compares libgit2's forward-slash delta paths against the caller's raw path with no normalization. **Breaks on Windows**: file-scoped `git_log` silently returns empty history.
- `ide/file_reader.rs:261` — `repo.status_file(rel)` handed an OS `Path`; on Windows that carries backslashes. **Breaks on Windows**: `get_file_metadata` always returns `git_status: null`.
- `ide/file_reader.rs:157-159`, `ide/file_search.rs:229-231`, `ide/file_tree.rs:217-220` — `canonicalize` returns `\\?\C:\…` on Windows and bare paths elsewhere; the `unwrap_or_else(raw)` fallback mixes the two in one `starts_with`. **Breaks differently on each platform**: on Windows a raw-vs-canonical comparison rejects legitimate paths; everywhere, the double-fallback opens the `..` escape.
- `commands/ide_commands.rs:202` — `resolve_safe` is purely lexical and never resolves symlinks. **Breaks on all three** (Unix symlinks; Windows junctions and directory symlinks).
- `ide/file_tree.rs:157` vs `:86` — `DirEntry::file_type` does not follow links while `fs::metadata` does; identical on all three platforms.
- `ide/file_tree.rs:142` — `eq_ignore_ascii_case` for directory skip matching. **Breaks on Linux**, where `Build/` and `build/` are distinct.
- `ide/symbol_nav.rs:178` — case-**sensitive** `SKIP_DIRS`, contradicting file_search.rs:217 and file_tree.rs:142. **Breaks on Windows and macOS**: `Node_Modules` is skipped by search but fully walked by symbol nav.
- `ide/file_reader.rs:147` — `lines()` + `join("\n")` silently converts CRLF to LF. **Breaks on Windows**.
- `ide/file_reader.rs:252` — `permissions().readonly()` has Windows FAT-attribute semantics. **Misleads on Linux and macOS**.
- `git/worktree.rs:118` — exact `PathBuf` equality. **Most fragile on Windows** (drive-letter case, trailing separators, `\\?\`) but unreliable on macOS too.
- `git/worktree.rs:126` — `remove_dir_all` on a live worktree with the result discarded. **Fails routinely on Windows** while still reporting success.
- `git/checkpoint.rs:87` — retention keys on the raw `file_path` string. **Breaks on Windows and macOS** (case forms create independent retention groups).
- `diff_analysis/risk_scorer.rs:21` — `"db/"` hardcodes a forward slash. **Breaks for Windows-separator diff input**.
- `diff_analysis/risk_scorer.rs:29-30,84` — `"Dockerfile"` matched case-sensitively. **Breaks on Linux** where lowercase `dockerfile` is common.
- `orphan/pid_checker.rs:7` — process-table presence treated as liveness. **Breaks on Linux and macOS** (zombies keep a dead worker's task claimed forever).
