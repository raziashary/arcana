# §0 · Scoring mechanics

**One scored area per phase.** Weights sum to 100, with the headline capability weighted heaviest.

Each area has **three binary rows**:

| Row | Means |
|---|---|
| **Build** | Every task in the phase is checked, each with a cited task ID and evidence class |
| **Smoke** | Every `S<p>-<nn>` in the phase passes |
| **Gates** | Every `TG-P<p>` gate assigned to the phase passes |

**Rules, without exception:**
- ✅ only with a **cited ID and an evidence class**. No partial credit. No "should work".
- Area % = rows checked ÷ 3.
- Overall = Σ (weight × area %).
- A gate **skipped** in CI counts as **failed** (§0.5 of the MDP).
- **A phase is never scored above its weakest row.** Build ✅ with Gates ❌ is 33%, not "nearly done".

## The safety overlay

Cross-cutting invariants, scored **independently of the phase areas**.

> **Any RED row caps overall readiness at 50%, regardless of the arithmetic.**

**Overlay rows are scored from "is the system actually guarded", not from gate colour.** A green gate on a guard that nothing calls is **AMBER**, and the reason is written in the row. This project has already produced four such guards — `Tool::requires_permission()` never called, the Fix-8c build sentinel unreachable by construction, the subagent recursion guard inert, and the `qc_review` evidence gate skipped on the native path. A matrix that scored those green would have been lying.

### §2.1 · Why `A3`'s Gates row is ☐ — the eight memory gates, clause by clause

Verified by a **fresh-context agent** that had not seen the reasoning behind
any of this code, briefed to the register's own standard: a gate is satisfied
only if *every* clause is met with a file:line and a test that reads state
back. Its headline structural finding drives four of the eight.

> **The vector/KNN leg does not exist in the shipped product.** `memories_vec`
> is `SELECT`ed in `embed.rs` and is **never created by any migration and never
> written**. The ladder has three rungs and none declares a `vec0` table. With
> the `embeddings` feature on and a model present, `VectorBackend::search`
> would fail with `no such table: memories_vec`. ⚠ This also qualifies
> **`P3-31`**: its proof that scope is a genuine pre-filter runs against a
> *throwaway* `vec0` table the test creates itself. It proves sqlite-vec
> honours a partition key. It does not prove this product does, because this
> product has no such table.

| Gate | Verdict | Why |
|---|---|---|
| **TG3-11** | NOT SATISFIED | Nothing asserts on **serialized request bytes**. The two candidates are a source-text grep and an assertion of the form `block.is_empty() \|\| block.contains("Memory")`, which cannot fail. `recall()` opens the real user DB, so there is no seam to inject a memory and observe it downstream — the gate is untestable without a refactor. |
