## Verified open observability and cross-phase findings

1. **Readable log redaction across writes.** Before the current fix, `RedactingWriter::write` redacted each buffer independently, so a recognizable credential split across calls could evade the patterns. The readable sink now buffers bounded records, redacts complete records, and omits a record that exceeds its 256 KiB buffer. The three focused readable-writer tests pass, including split writes separated by a flush and oversized-record omission. Full telemetry producer/redaction privacy coverage remains open.
2. **MCP wire-response bound.** `external_mcp.rs::execute_call_with_client` obtains the parsed RMCP result before `bounded_json` applies the 64 KiB serialized-result limit. `max_sse_event_size` limits one SSE event, not total transport buffering. Add a total streamed response bound before parsing/buffering and prove it with a local oversized MCP wire response. Keep redirects, cancellation and consent requirements separately tracked.
3. **Active log retention tie-break.** `log_retention.rs::prune_at_with_limit` now prioritizes the current active filename before date sorting. The regression keeps today's log open while pruning alongside five valid future-dated recognized files, then appends and reads back the post-prune marker. `cargo test -p arcana-core --lib observability::log_retention::tests --locked -- --test-threads=1` passes 6/6.
4. **CLI log retention startup.** Fixed. Both Tauri and CLI now call the shared `log_retention::prune_default()` after logger initialization. `cli_startup_prunes_both_shared_log_streams_and_keeps_today_active` launches the real CLI in a disposable profile with six readable and six structured recognized files, then verifies five remain in each stream and today's active paths survive. Exact test passes 1/1. This closes only the CLI-startup consumer slice; table retention and full observability remain open.
5. **Append-only analytics retention.** The P4-59 lifecycle currently schedules worker-stat retention, while `token_usage`, `system_events`, `api_failures`, and `hook_logs` have no verified production pruning consumer. Define and enforce an age/size policy for each table, expose cleanup failure, and test each production lifecycle without destructive access to user data.
6. **Supervisor health completeness.** `list_worker_health.rs` exposes live run/journal state, but P4-54 still requires retry counters, model/token usage, parent/child relationships and recovery continuation. Prove the registered Supervisor reader returns those fields from a real worker scenario.
7. **Producer-to-Logs UI integration.** Rust persistence/reader and frontend IPC-mocked tests separately pass, but there is no single proof across a real event producer, persisted file, registered Tauri reader, and rendered Logs UI. Keep TG4-24 open until a live host integration verifies that path.
8. **SQLite setup/initializer transaction spans.** `db::open_tuned` has no fixed-label operation result span, `WorkersDb::open_at` lacks a parent result span covering repair/seed work, and `DailyCap::save` lacks a parent event whose success is set only after transaction commit. Add privacy-safe parent spans and tests for success/failure where their owning P4 observability scope requires them.
