## Shared helper

`arcana-core/src/db/timestamps.rs` defines `now_rfc3339` and `format_utc_timestamp` (fixed-millisecond RFC 3339 UTC with `Z`), `SQLITE_UTC_NOW` (the matching SQLite `strftime` expression), `parse_db_timestamp`, and `parse_row_timestamp`. Reads below that are mapped through `row.get` retain the source string; they are readable as raw string data but are not parser validation unless the reader explicitly calls the helper or SQLite `julianday` for chronology.

## Finite findings and proof gaps

1. **No TasksDb/RunsDb annual property proof is named.** The mapped suites cover selected canonical writes, mixed legacy strings, and `julianday` instant ordering, but no named test generates a full-year corpus with leap day, local-midnight boundaries, and both-hemisphere DST transitions at each physical writer→reader pair. The current CI cross-platform timestamp filter is `analytics_timestamp_pairs_`; it targets analytics/session/hook pairs and does not establish TasksDb/RunsDb annual coverage. This is a proof gap across the scoped pair inventory, not evidence that current outputs fail.
2. **Legacy proof is selective, not pair-complete.** TasksDb legacy proof found for `tasks.created_at/updated_at` is `production_task_reader_returns_canonical_timestamps_and_legacy_rows_survive_upgrade`; RunsDb mixed-format ordering/upgrade proof exists for `runs.started_at` in `production_run_chronology_reads_mixed_timestamp_formats_by_instant`, `production_worker_run_readers_select_latest_instant_across_legacy_rows`, and `runs_v7_upgrade_preserves_rows_and_indexes_instant_order_readers`. `active_worker_operation_reads_canonical_and_legacy_timestamps` covers operation-intent parsing. Other scoped columns have no named legacy-row assertion in the inspected tests.
3. **Persisted timestamps without timestamp consumer pairs:** `project_build_batches.created_at` has no production reader found; `project_build_batches.completed_at` is used only by predicates/checks; `build_retry_approvals.created_at/consumed_at` have no application projection; `operation_journal.created_at` on reconciliation rows is not selected by a result projection. These are unpaired timestamp inventory entries, not parser/order vulnerabilities in an existing consumer.
4. **Canonical writer paths are present for the inspected production writes.** TasksDb has SQL defaults and canonicalizing triggers matching `SQLITE_UTC_NOW`, plus explicit canonical SQLite-now completion/resolution writes; RunsDb methods bind `now_rfc3339()`. Most model projections intentionally return stored strings, so canonical writer evidence does not establish parsing at each read path.
5. **No current raw lexical-ordering defect was identified in these two DB modules.** The inspected timestamp chronology/order queries use SQLite `julianday(...)` (with `id` tie-breaking where present); the mixed-format RunsDb ordering tests exercise instant ordering. The `RunsDb` raw-string fields remain a parser-coverage limitation where a caller needs instant semantics, but no failing production consumer was demonstrated from source inventory alone.
