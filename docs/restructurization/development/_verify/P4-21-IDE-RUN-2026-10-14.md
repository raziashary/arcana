# P4-21 IDE Run: Windows production command path

The IDE now offers a user-initiated Run action for its opened file. The Tauri command resolves the selected workspace and calls the core project's fixed-argv `Run` intent. The core checks that the file exists within that workspace, selects only containing projects, uses the file's ecosystem where possible, and requires a validated selector for an ambiguous result. It launches through the same OS sandbox as `project_command`; it does not create a worker claim or QC build evidence. The action returns bounded output and exit status, with a 120-second process limit. Python has no defined project `Run` intent and reports that explicitly.

Windows proof on 2026-10-14:

- `cargo test --offline -p arcana-core --lib ide_run_uses_opened_file_project_and_sandbox_without_a_task_claim --locked -- --test-threads=1`: 1 passed. An isolated workspace contains Cargo and Node manifests; an opened Rust source file selects `cargo run`, the sandboxed program exits 0, and its output is read back. Outside-workspace paths and a mismatched Python selector are denied.
- `cargo check --offline -p arcana --locked`: passed; the registered Tauri command compiles through the desktop crate.
- `npm run test -- src/tabs/IDE.test.tsx src/utils/ideNavigation.test.ts src/stores/ideStore.test.ts`: 8 passed. The UI calls the registered command with the active file, accepts a selected toolchain, displays result/error, and disables Run while a file loads or a command is pending. Existing navigation/store tests exercise the listener and opened-file state with mocked IPC.
