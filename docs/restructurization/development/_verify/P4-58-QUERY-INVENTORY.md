## Remaining production query families

Migration-owned lifecycle trigger reads are part of the expanded task-health /
lifecycle scope. The epic-completion guard's two child predicates are checked
against a populated 5,000-task fixture and both use the measured epic index in
`epic_progress_readers_use_measured_indexes_with_populated_tasks`; the QC
evidence predicate uses the indexed production latest-evidence query and its
populated QC transition test. SQLite omits trigger subprogram plans from
`EXPLAIN QUERY PLAN UPDATE`, so these inner predicates are explained directly
and their trigger behavior is tested through real lifecycle writes. Status
string checks and claim-metadata triggers have no row-reading SQL.

evidence only: each fingerprint row repeats its owner's populated-plan/result
