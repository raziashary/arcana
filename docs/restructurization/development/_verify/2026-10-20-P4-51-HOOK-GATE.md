# P4-51 — Hook refusal: policy denial vs infrastructure failure

**Date:** 2026-10-20
**Decision:** `ADR-LOG-RESTRUCT-0402`
**Task:** `P4-51` (the hook half of its "handler, parse, permission, timeout, cancellation and
infrastructure failures" contract), and W8's remaining half.

## Defect

`HookRegistry::fire` returned `bool`; `fire_with_logs` returned `Vec<HookExecutionLog>`. Three
different facts collapsed into the same value: no hook matched, a hook refused, and the hooks
store could not be opened or decoded. The denial direction was right and stays (ADR-0380 made the
readers propagate decode errors for exactly this reason), but `tool_executor` reported every
`false` as `permission_denied` / "blocked by a hook". A user whose `config.db` was unreadable was
therefore told to review a hook policy that had never run.

Two `write_file` tests had already been written around the conflation — they inject checkpoint
failures through a trigger rather than a damaged `config.db` *specifically so the hook reader does
not refuse first*, with comments saying so. That is the evidence that the conflation was
load-bearing rather than cosmetic.

## Change

| File | Change |
|---|---|
| `hooks/registry.rs` | `HookGate { Allowed, Denied { hook, reason }, Unavailable(String) }`; `fire` delegates to `fire_gate` and keeps its boolean contract; `fire_with_logs` returns `(logs, gate)`; one loop, so the boolean and diagnostic paths cannot drift. |
| `agent/tool_executor.rs` | PreToolUse consumes `fire_gate`: policy denial → `permission_denied`/`permission`; unevaluable policy → `hook_evaluation_failed`/`infrastructure`, with next-step text that says it is not a policy decision. |
| `hooks/mod.rs` | Usage comment updated to the new shapes. |

`fire_with_logs` had no production caller (one usage comment), so its shape was changed rather
than wrapped.

## Evidence

```
cargo test -p arcana-core --lib -- --test-threads=1 registry::gate_tests
test hooks::registry::gate_tests::an_unreadable_hook_store_is_unavailable_not_denied ... ok
test hooks::registry::gate_tests::a_store_with_no_matching_hook_allows_the_action ... ok
test hooks::registry::gate_tests::a_blocking_hook_is_denied_and_names_itself ... ok
test result: ok. 3 passed; 0 failed
```

- Unreadable store: `Unavailable`, `permits() == false`, reason says "could not be evaluated" and
  does not claim a policy decision.
- Empty store: `Allowed`.
- Blocking hook: `Denied { hook: "freeze-writes", .. }` and the hook's own message survives.

Consumer proof — the malformed-row regression now asserts the envelope:

```
agent::tool_executor::p8_execution_registry_tests::malformed_hook_configuration_blocks_the_registered_file_handler ... ok
assert_eq!(refusal["error_code"], "hook_evaluation_failed");
assert_eq!(refusal["error"]["category"], "infrastructure");
```

**Falsification.** The `Unavailable` arm was temporarily mapped back to
`permission_denied`/`permission` and the consumer test re-run:

```
... malformed_hook_configuration_blocks_the_registered_file_handler ... FAILED
assertion `left == right` failed
  left: String("permission_denied")
 right: "hook_evaluation_failed"
```

Reverted; green again. `cargo fmt --all -- --check` reports only the known owner-WIP
`process_sandbox/linux_smoke/staging.rs:572`.
